## 1. C++20 现代特性速览

### 1.1 `std::atomic<bool>` — 无锁线程安全标志

项目中所有的线程停止标志都使用了 `std::atomic<bool>`，而不是普通的 `bool`：

```cpp
// FFmpegRecorder.h
std::atomic<bool> m_isRecording;
std::atomic<bool> m_softStopRequested;

// WasapiCapturer.h
std::atomic<bool> m_stopRequested;
```

**为什么不用普通 bool？**

普通 `bool` 在多线程下存在**数据竞争（Data Race）**问题：一个线程写入，另一个线程读取，结果是未定义行为（Undefined Behavior）。

`std::atomic<bool>` 保证：
- 读写操作是**原子的**（不可分割）
- 对其他线程的写入是**立即可见的**（内存可见性）
- 无需加锁，性能优于 `QMutex`

```cpp
// 采集线程循环（伪代码）
while (!m_stopRequested.load()) {   // 原子读，安全
    captureNextFrame();
}

// 主线程停止
m_stopRequested.store(true);        // 原子写，采集线程立刻感知
```

### 1.2 Lambda 表达式

项目中大量使用 Lambda，尤其是在 `connect` 中：

```cpp
// SystemController.cpp
connect(bus, &EventBus::cmd_removeOverlay, this, [this](int id) {
    if (m_capturer)
        QMetaObject::invokeMethod(m_capturer, "removeOverlay",
                                  Qt::QueuedConnection, Q_ARG(int, id));
    QMutexLocker locker(&m_poolMutex);
    for (int i = 0; i < m_activeLayers.size(); ++i) {
        if (m_activeLayers[i]->itemId == id) {
            delete m_activeLayers[i];
            m_activeLayers.removeAt(i);
            break;
        }
    }
});
```

Lambda 语法结构：

```cpp
[捕获列表](参数列表) -> 返回类型 {
    函数体
}
```

**捕获列表**说明：

| 写法 | 含义 |
|------|------|
| `[this]` | 捕获当前对象指针（最常用） |
| `[=]` | 按值捕获所有局部变量 |
| `[&]` | 按引用捕获所有局部变量 |
| `[isMic]` | 按值捕获指定变量 |
| `[this, isMic]` | 同时捕获 this 和 isMic |

> ⚠️ **注意**：在 Qt 中用 `[this]` 捕获时，如果对象被销毁后 Lambda 仍被调用（如跨线程信号），会导致悬空指针崩溃。可以用 `QPointer<T>` 保护，或确保连接时使用正确的生命周期管理。

### 1.3 范围 for 循环

```cpp
for (int i = 0; i < m_activeLayers.size(); ++i) { ... }   // 传统写法

// 等价的范围 for（推荐）
for (auto* layer : m_activeLayers) { ... }
```

### 1.4 结构体默认成员初始化（C++11+，项目大量使用）

```cpp
// RecorderConfig.h
struct RecorderConfig {
    int width = 1920;               // 直接在声明处初始化
    int fps = 30;
    bool enableStreaming = false;
    QString encoderName = "h264_nvenc";
};

// SystemController.h
struct CameraContext {
    int itemId;
    QString deviceId;
    WinRTCamera* camera = nullptr;  // 指针默认初始化为空
};
```

这种写法避免了构造函数中忘记初始化成员的问题，是现代 C++ 的推荐实践。

## 2. Qt 元对象系统（MOC）

### 2.1 Q_OBJECT 宏

```cpp
class EventBus : public QObject
{
    Q_OBJECT   // ← 必须放在 class 内最开始
public:
    ...
signals:
    void cmd_toggleRecording(bool start);
};
```

`Q_OBJECT` 宏告诉 Qt 的 MOC（Meta-Object Compiler）工具：这个类需要元对象支持。MOC 会自动生成以下功能：
- 信号（signals）的实现代码
- 运行时类型信息（`className()`、`inherits()`）
- 属性系统（`Q_PROPERTY`）
- 动态调用（`QMetaObject::invokeMethod`）

> **编译流程**：`.h` 文件 → MOC 处理 → 生成 `moc_xxx.cpp` → 一起编译链接

### 2.2 信号与槽的本质

Qt 信号槽不是语言层面的特性，而是通过 MOC 代码生成实现的：

```cpp
// 信号声明（只需声明，MOC 自动生成实现）
signals:
    void cmd_toggleRecording(bool start);

// 发射信号
emit cmd_toggleRecording(true);
// 等价于：
// EventBus::cmd_toggleRecording(true);  ← MOC 生成的函数

// 槽函数（普通成员函数，无特殊限制）
private slots:
    void onToggleRecording(bool start);
```

### 2.3 connect 的四种写法对比

项目中主要使用**函数指针写法**（Qt5+ 推荐）：

```cpp
// ✅ 写法1：函数指针（编译期检查，推荐）
connect(bus, &EventBus::cmd_toggleRecording,
        this, &SystemController::onToggleRecording);

// ✅ 写法2：Lambda（灵活，适合简单逻辑）
connect(m_durationTimer, &QTimer::timeout, this, [this]() {
    onDurationTimer();
});

// ⚠️ 写法3：字符串（旧写法，运行期检查，不推荐）
connect(bus, SIGNAL(cmd_toggleRecording(bool)),
        this, SLOT(onToggleRecording(bool)));

// ✅ 写法4：指定连接类型（跨线程时必须）
connect(m_capturer, &DxGiCapturer::frameCaptured,
        this, &SystemController::onVideoFrameCaptured,
        Qt::QueuedConnection);  // ← 第5个参数
```

## 3. Qt 连接类型（最重要！）

`connect` 的第5个参数决定了信号如何跨线程传递，这是音视频项目中最容易出错的地方。

### 3.1 五种连接类型

| 类型 | 行为 | 适用场景 |
|------|------|----------|
| `Qt::AutoConnection`（默认） | 同线程→直接调用，跨线程→队列 | 通用，大多数情况 |
| `Qt::DirectConnection` | 在发射线程中**直接调用**槽函数 | 同线程，或需要即时响应 |
| `Qt::QueuedConnection` | 将槽函数**投递到接收对象所在线程**的事件队列 | 跨线程（最常用） |
| `Qt::BlockingQueuedConnection` | 跨线程调用，发射线程**阻塞等待**槽函数执行完毕 | 需要同步结果时 |
| `Qt::UniqueConnection` | 同一对槽只连接一次（防重复） | 特殊需求 |

### 3.2 在项目中的实际应用

```cpp
// SystemController.cpp - 采集线程 → 主线程（需排队）
connect(m_capturer, &DxGiCapturer::frameCaptured,
        this, &SystemController::onVideoFrameCaptured,
        Qt::QueuedConnection);  // m_capturer 在视频线程，this 在主线程

// 停止采集时，主线程需要等待视频线程执行完毕
QMetaObject::invokeMethod(m_capturer, "stopCapture",
                          Qt::BlockingQueuedConnection);
// BlockingQueuedConnection：主线程会阻塞，直到视频线程中的 stopCapture() 执行完
```

### 3.3 QueuedConnection 的工作原理

```
视频线程：emit frameCaptured(img)
    │
    ▼
Qt 事件系统：将 (接收者=this, 槽=onVideoFrameCaptured, 参数=img) 打包成事件
    │
    ▼（等待主线程事件循环）
主线程事件循环（a.exec()）：取出事件，调用 onVideoFrameCaptured(img)
```

信号参数（`img`）会被**深拷贝**一份存入队列，因此不存在内存安全问题。  
这就是为什么 `QImage` 这类可拷贝对象可以安全地跨线程传递。

## 4. Qt 多线程：两种 QThread 用法

项目中同时使用了两种截然不同的 `QThread` 使用方式，必须理解其区别。

### 4.1 方式一：继承 QThread（FFmpegRecorder、WasapiCapturer）

```cpp
// FFmpegRecorder.h
class FFmpegRecorder : public QThread
{
    Q_OBJECT
protected:
    void run() override;  // 在新线程中执行的代码
};

// 使用
m_recorder = new FFmpegRecorder(nullptr);
m_recorder->start();  // 调用 start() → 内部调用 run()
```

**适用场景**：有一个明确的"主循环"需要持续运行（如编码循环、音频采集循环）。

```cpp
// FFmpegRecorder.cpp - run() 中是编码主循环
void FFmpegRecorder::run() {
    while (m_isRecording.load()) {
        // 取帧、编码、写文件...
    }
}
```

### 4.2 方式二：moveToThread（DxGiCapturer）

```cpp
// SystemController.cpp
m_videoThread = new QThread(this);
m_capturer = new DxGiCapturer();
m_capturer->moveToThread(m_videoThread);  // 将对象移到新线程

connect(m_videoThread, &QThread::started, m_capturer, [this]() {
    m_capturer->init();
    m_capturer->startCapture();
});

m_videoThread->start();
```

`moveToThread` 后，`m_capturer` 的所有槽函数都在 `m_videoThread` 中执行。

**适用场景**：对象需要响应事件（通过槽函数），而不仅仅是跑一个循环。

### 4.3 两种方式对比

| 对比项 | 继承 QThread | moveToThread |
|--------|-------------|--------------|
| 线程内容 | `run()` 函数体 | 事件循环（槽函数） |
| 槽函数执行线程 | ❌ 仍在主线程 | ✅ 在新线程 |
| 适合场景 | 持续运行的循环 | 事件驱动的任务 |
| 项目中的例子 | `FFmpegRecorder`、`WasapiCapturer` | `DxGiCapturer` |

> ⚠️ **常见误解**：继承 QThread 后，类的**槽函数**仍然在**创建该对象的线程**中执行，只有 `run()` 在新线程中。这是初学者最容易犯的错误！

### 4.4 线程的安全停止

```cpp
// WasapiCapturer — 通过 atomic 标志停止
void WasapiCapturer::stop() {
    m_stopRequested.store(true);  // 设置停止标志
}

void WasapiCapturer::run() {
    while (!m_stopRequested.load()) {
        // 采集音频...
    }
}

// 外部：停止并等待线程完全结束
m_micCapturer->stop();
m_micCapturer->wait();  // 阻塞直到 run() 返回
```

`wait()` 的重要性：不等待直接 `delete` 线程对象，如果线程还在运行，会导致崩溃。

## 5. QMutex 与 QMutexLocker

### 5.1 QMutexLocker（RAII 风格）

```cpp
// SystemController.cpp
QMutex m_poolMutex;

// ❌ 手动加解锁（容易忘记 unlock，异常时更糟）
m_poolMutex.lock();
// ... 操作共享数据 ...
m_poolMutex.unlock();  // 如果中间 return 或抛异常，unlock 不会执行！

// ✅ QMutexLocker（推荐）
{
    QMutexLocker locker(&m_poolMutex);  // 构造时加锁
    // ... 操作共享数据 ...
}   // locker 析构时自动 unlock，异常安全
```

RAII（Resource Acquisition Is Initialization）是 C++ 资源管理的核心惯用法：资源在构造时获取，在析构时释放，无论正常退出还是异常退出都能正确释放。

### 5.2 项目中的典型用法

```cpp
// FFmpegRecorder.h
QMutex m_videoMutex;
QQueue<VideoFrameData> m_videoQueue;

// 采集线程推帧（生产者）
void FFmpegRecorder::pushVideoFrame(const QImage &img, qint64 timestamp) {
    QMutexLocker locker(&m_videoMutex);
    m_videoQueue.enqueue({img, timestamp});
}

// 编码线程取帧（消费者）— 在 run() 中
void FFmpegRecorder::run() {
    while (m_isRecording.load()) {
        VideoFrameData frameData;
        {
            QMutexLocker locker(&m_videoMutex);
            if (!m_videoQueue.isEmpty())
                frameData = m_videoQueue.dequeue();
        }   // 释放锁后再编码，避免长时间持锁
        if (frameData.image.isNull()) continue;
        processVideo(frameData);
    }
}
```

这是经典的**生产者-消费者**模式：`QMutex` 保护共享队列，`QQueue` 作为缓冲区。

## 6. qRegisterMetaType — 跨线程类型注册

### 6.1 为什么需要注册？

Qt 的 `QueuedConnection` 在跨线程传递信号参数时，需要在 Qt 的元类型系统中找到该类型的拷贝构造函数，以便将参数打包进事件队列。

对于 Qt 内置类型（`int`、`QString`、`QImage` 等），Qt 已经自动注册了。  
对于自定义类型（如 `QList<int>`），必须手动注册：

```cpp
// main.cpp
qRegisterMetaType<QList<int>>("QList<int>");
```

### 6.2 不注册会发生什么？

```
QObject::connect: Cannot queue arguments of type 'QList<int>'
(Make sure 'QList<int>' is registered using qRegisterMetaType().)
```

信号参数丢失，槽函数收到的是空数据，逻辑错误且难以排查。

### 6.3 注册时机

**必须在第一次使用该类型的 `connect` 之前注册**，通常放在 `main()` 函数开头：

```cpp
int main(int argc, char *argv[]) {
    CrashHandler::init();
    Logger::instance().init("app_log.txt");
    qRegisterMetaType<QList<int>>("QList<int>");  // ← 尽早注册
    QApplication a(argc, argv);
    // ...
}
```

## 7. QMetaObject::invokeMethod — 跨线程调用

有时候需要在特定线程上调用一个函数，但不能直接用 `connect`（因为没有合适的信号）。

`QMetaObject::invokeMethod` 就是为此设计的：

```cpp
// SystemController.cpp

// 方式1：异步调用（等价于 QueuedConnection）
QMetaObject::invokeMethod(m_capturer, "removeOverlay",
                          Qt::QueuedConnection,
                          Q_ARG(int, id));
// → 将 removeOverlay(id) 的调用投递到 m_capturer 所在线程

// 方式2：同步调用（等价于 BlockingQueuedConnection）
QMetaObject::invokeMethod(m_capturer, "stopCapture",
                          Qt::BlockingQueuedConnection);
// → 当前线程阻塞，直到 m_capturer 线程中的 stopCapture() 执行完毕
```

**注意**：`invokeMethod` 的函数名是字符串，是运行时查找的，被调用的函数必须是 `Q_INVOKABLE` 或 `slot`，且参数类型必须已注册（这就是为什么 `QList<int>` 需要注册）。

## 8. COM 智能指针 ComPtr

Windows API 大量使用 COM（Component Object Model）接口，需要手动管理引用计数。`ComPtr<T>` 是 WRL（Windows Runtime Library）提供的 RAII 智能指针：

```cpp
// WasapiCapturer.h
#include <wrl/client.h>
using Microsoft::WRL::ComPtr;

ComPtr<IMMDeviceEnumerator> m_enumerator;  // 自动管理引用计数
ComPtr<IMMDevice> m_device;
ComPtr<IAudioClient> m_audioClient;
```

对比裸指针的优势：

```cpp
// ❌ 裸指针（需要手动 Release，极易泄漏）
IMMDeviceEnumerator* enumerator = nullptr;
CoCreateInstance(..., &enumerator);
// ... 使用 ...
enumerator->Release();  // 忘记调用 → 内存泄漏

// ✅ ComPtr（析构时自动 Release）
ComPtr<IMMDeviceEnumerator> enumerator;
CoCreateInstance(..., &enumerator);
// ... 使用 ...
// 无需手动 Release，ComPtr 析构时自动调用
```

`ComPtr` 常用方法：
- `enumerator.Get()` — 获取裸指针（传给需要 T* 的 API）
- `&enumerator` — 获取 T** 指针（用于输出参数）
- `enumerator.Reset()` — 提前释放
- `enumerator.As(&other)` — 查询另一个接口（QueryInterface）

## 9. 综合案例：追踪一个信号的完整旅程

以"用户切换音频设备"为例，追踪信号从 UI 到底层模块的完整流程：

```
【主线程 - UI 层】
SettingsDialog 用户选择新麦克风
    │
    ▼
EventBus::instance()->sendCommandChangeAudioDevice(true, deviceId)
    │ emit cmd_changeAudioDevice(true, deviceId)
    │
    ▼（QueuedConnection，投递到主线程事件队列）
【主线程 - SystemController】
SystemController::onChangeAudioDevice(true, deviceId)
    │
    ├─ 停止旧的 WasapiCapturer（m_micCapturer->stop(); m_micCapturer->wait()）
    │
    └─ 创建新的 WasapiCapturer，设置新设备，start()
         │
         ▼（WasapiCapturer 继承 QThread，run() 在新线程）
【音频线程 - WasapiCapturer::run()】
    循环采集 PCM 数据
         │ emit audioDataReady(data, sampleRate, channels)
         │
         ▼（Lambda slot，在主线程执行）
【主线程 - Lambda】
    m_recorder->pushAudioData(1, data, sampleRate, channels)
         │（QMutex 保护队列）
         ▼
【编码线程 - FFmpegRecorder::run()】
    从队列取出音频数据，编码为 AAC，写入 MP4
```

这个追踪揭示了三个关键点：
1. UI 与 Controller 之间通过 **EventBus** 解耦
2. **QueuedConnection** 保证跨线程调用安全
3. **QMutex + QQueue** 实现跨线程数据传递
