## 1. 开发环境搭建

### 1.1 安装 Qt 6

1. 前往 [https://www.qt.io/download-qt-installer](https://www.qt.io/download-qt-installer) 下载 Qt Online Installer
2. 安装时勾选以下组件：
   - `Qt 6.x.x` → `MSVC 2022 64-bit`
   - `Qt 6.x.x` → `Qt Multimedia`
   - `Qt 6.x.x` → `Qt Concurrent`
   - `Developer and Designer Tools` → `Qt Creator`
   - `Developer and Designer Tools` → `CMake`（可选）

3. 安装完成后，打开 Qt Creator，进入 `Edit → Preferences → Kits`，确认 MSVC 工具链已被自动检测到。

### 1.2 安装 Visual Studio（MSVC 编译器）

Qt 项目使用 MSVC 编译器，需要安装 Visual Studio 2022（Community 版免费）：

1. 下载 Visual Studio 2022 Installer
2. 勾选工作负载：`使用 C++ 的桌面开发`
3. 确保安装了 `Windows 11 SDK`（WGC、WinRT API 需要）

### 1.3 配置 FFmpeg

本项目依赖 FFmpeg 7.x 的预编译库。

1. 从 [https://github.com/BtbN/FFmpeg-Builds/releases](https://github.com/BtbN/FFmpeg-Builds/releases) 下载  
   选择：`ffmpeg-master-latest-win64-gpl-shared.zip`（包含 .dll 和 .lib）

2. 解压到固定路径，例如 `D:/DownLoad/ffmpeg`，目录结构应为：
   ```
   D:/DownLoad/ffmpeg/
   ├── bin/          ← .dll 动态库（运行时需要）
   ├── include/      ← 头文件
   └── lib/          ← .lib 导入库（编译时链接）
   ```

3. 将 `D:/DownLoad/ffmpeg/bin` 添加到系统环境变量 `PATH`，或在运行时将 .dll 复制到可执行文件目录。

> **注意**：项目 `untitled5.pro` 中硬编码了路径 `D:/DownLoad/ffmpeg`，如果你的路径不同，需要修改 `.pro` 文件中的 `FFMPEG_PATH` 变量。

## 2. 打开并编译项目

1. 用 Qt Creator 打开 `untitled5.pro`
2. 选择 Kit：`Desktop Qt 6.x.x MSVC2022 64bit`
3. 点击左下角 `Build`（锤子图标）
4. 首次编译可能需要几分钟，成功后点击 `Run`（绿色三角）

**常见编译错误排查**：

| 错误信息 | 原因 | 解决方案 |
|----------|------|----------|
| `cannot open file 'avcodec.lib'` | FFmpeg 路径错误 | 检查 `.pro` 中的 `FFMPEG_PATH` |
| `'winrt/base.h' not found` | Windows SDK 版本过低 | 安装 Windows 11 SDK 10.0.22000+ |
| `LNK2019: unresolved external symbol` | 缺少链接库 | 检查 `.pro` 中的 `LIBS` 配置 |
| `d3d11.h not found` | 缺少 DirectX SDK | 安装 Windows SDK |

## 3. 解读 untitled5.pro

`.pro` 文件是 Qt qmake 的工程描述文件，相当于 CMakeLists.txt 或 Makefile 的角色。

```pro
QT += core gui widgets multimedia multimediawidgets concurrent
```
声明使用的 Qt 模块：
- `widgets`：传统桌面 UI（QWidget、QDialog 等）
- `multimedia`：摄像头、音频设备枚举
- `concurrent`：`QtConcurrent::run` 线程池

```pro
CONFIG += c++20
```
启用 C++20 标准，项目中用到了 `std::atomic`、Lambda 等现代特性。

```pro
QMAKE_CXXFLAGS += /permissive- /Zc:twoPhase-
```
这两个 MSVC 编译选项对 WGC（Windows Graphics Capture）至关重要：
- `/permissive-`：开启严格标准兼容模式，WinRT 头文件需要此选项
- `/Zc:twoPhase-`：关闭两阶段名称查找，解决 WinRT 模板解析问题

```pro
LIBS += -ld3d11 -ldxgi -ld3dcompiler -ldwmapi -lwindowsapp -luser32 -lmmdevapi -lole32
```
链接的 Windows 系统库：
- `d3d11`：Direct3D 11（GPU 纹理操作）
- `dxgi`：DXGI 屏幕采集
- `windowsapp`：WinRT / UWP API
- `mmdevapi`：Windows 音频设备 API（WASAPI）
- `ole32`：COM 基础库

```pro
win32 {
    FFMPEG_PATH = D:/DownLoad/ffmpeg
    INCLUDEPATH += $$FFMPEG_PATH/include
    LIBS += -L$$FFMPEG_PATH/lib -lavcodec -lavformat -lavutil -lswscale -lswresample
}
```
FFmpeg 库配置：`INCLUDEPATH` 添加头文件路径，`LIBS` 链接各个子库。

## 4. 逐行解读 main.cpp

```cpp
int main(int argc, char *argv[])
{
    // 1. 初始化崩溃捕获
    CrashHandler::init();
```
**第一步就初始化崩溃捕获**，这是生产级应用的标准做法。  
`CrashHandler::init()` 向 Windows 注册了一个全局异常处理函数，一旦程序崩溃，会自动生成 `.dmp` 文件，方便事后分析。

```cpp
    // 2. 初始化日志
    Logger::instance().init("app_log.txt");
    LOG_INFO("Application Launching...");
```
日志系统紧随其后初始化。`Logger` 是一个单例，`init()` 打开日志文件，之后所有模块都可以通过 `LOG_INFO` / `LOG_ERROR` 等宏写入日志。

```cpp
    qRegisterMetaType<QList<int>>("QList<int>");
```
**这行代码非常关键**，注释已经解释了原因：Qt 的跨线程信号槽（`Qt::QueuedConnection`）在传递自定义类型时，需要先用 `qRegisterMetaType` 注册，否则运行时会报警告并且参数传递失败。

```cpp
    QApplication::setAttribute(Qt::AA_EnableHighDpiScaling);
    QApplication::setAttribute(Qt::AA_UseHighDpiPixmaps);
```
高分屏适配，确保在 4K 显示器上 UI 不会模糊。

```cpp
    QApplication a(argc, argv);

    try {
        SystemController controller;
        controller.initialize();

        MainWindow w;
        w.show();

        return a.exec();
    } catch (const std::exception& e) { ... }
```
**初始化顺序很重要**：
1. `SystemController` 先于 `MainWindow` 创建，因为 UI 需要通过 EventBus 与 Controller 通信
2. `a.exec()` 进入 Qt 事件循环，程序在此阻塞直到窗口关闭
3. 整个主逻辑包裹在 `try-catch` 中，捕获未处理的 C++ 异常

## 5. 深入 Logger.h

Logger 是整个项目的基础设施，理解它的设计对后续阅读所有模块都有帮助。

### 5.1 单例模式

```cpp
static Logger& instance() {
    static Logger instance;  // C++11 保证线程安全的局部静态变量
    return instance;
}
```
使用 Meyers Singleton（局部静态变量），C++11 标准保证多线程下只初始化一次，无需手动加锁。

### 5.2 为什么用 QRecursiveMutex 而不是 QMutex？

```cpp
QRecursiveMutex m_mutex;  // 递归锁
```

普通 `QMutex` 不允许同一线程重复加锁（会死锁）。`init()` 函数内部调用了 `log()`，而两者都需要加锁：

```
init() 加锁 → 调用 log() → log() 再次加锁 → 死锁！
```

换成 `QRecursiveMutex` 后，同一线程可以多次加锁，每次加锁对应一次解锁，彻底解决这个问题。

> 这是项目历史上真实踩过的坑，在"实现EventBus和无边框风格"版本的目录名中就记录了"奔溃问题"。

### 5.3 日志宏

```cpp
#define LOG_INFO(msg)  Logger::instance().log(LogLevel::INFO, msg, __FILE__, __LINE__, __FUNCTION__)
#define LOG_WARN(msg)  Logger::instance().log(LogLevel::WARNING, msg, __FILE__, __LINE__, __FUNCTION__)
#define LOG_ERROR(msg) Logger::instance().log(LogLevel::CRITICAL, msg, __FILE__, __LINE__, __FUNCTION__)
#define LOG_TRACE(msg) Logger::instance().log(LogLevel::DEBUG_TRACE, msg, __FILE__, __LINE__, __FUNCTION__)
```

`__FILE__`、`__LINE__`、`__FUNCTION__` 是 C++ 预定义宏，在编译时展开为当前文件名、行号、函数名。这样每条日志都自动携带位置信息，调试时一眼就能定位到出问题的代码行。

输出格式示例：
```
2026-04-12 10:23:45.123 [12345] [INFO] [main:17] Application Launching...
```

### 5.4 立即刷新（flush）

```cpp
m_stream << logLine << "\n";
m_stream.flush();  // 立即刷新，防止崩溃时日志丢失
```

如果不立即 flush，日志数据会停留在内存缓冲区，程序崩溃时缓冲区内容会丢失。`flush()` 强制将缓冲区写入磁盘，确保崩溃前的最后几条日志也能保留。

## 6. 深入 CrashHandler.h

```cpp
static void init() {
    SetUnhandledExceptionFilter(UnhandledExceptionFilter);
}
```

`SetUnhandledExceptionFilter` 是 Windows API，注册一个全局的"最后防线"异常处理函数。当程序发生未捕获的异常（空指针、访问越界等）时，Windows 会调用这个函数，而不是直接弹出"程序已停止工作"对话框。

```cpp
HANDLE hFile = CreateFileW(fileName.toStdWString().c_str(), GENERIC_WRITE, ...);

MINIDUMP_TYPE dumpType = (MINIDUMP_TYPE)(
    MiniDumpNormal |
    MiniDumpWithHandleData |
    MiniDumpWithIndirectlyReferencedMemory
);

MiniDumpWriteDump(GetCurrentProcess(), GetCurrentProcessId(), hFile, dumpType, &mdei, nullptr, nullptr);
```

`MiniDumpWriteDump` 将当前进程的内存快照写入 `.dmp` 文件，包含：
- 所有线程的调用栈
- 寄存器状态
- 栈内存引用的数据

生成的 `.dmp` 文件可以用 Visual Studio 或 WinDbg 打开，精确定位到崩溃的代码行。

> **注意**：这里选择了 `MiniDumpNormal` 而不是 `MiniDumpWithFullMemory`，生成的文件很小（通常几百KB），不会包含完整堆内存，适合生产环境。

## 7. 解读 RecorderConfig.h

```cpp
struct RecorderConfig {
    int width = 1920;
    int height = 1080;
    int fps = 30;
    int videoBitrate = 6000000;       // 6 Mbps
    QString encoderName = "h264_nvenc"; // 硬件编码器

    bool enableFileRecord = true;
    QString savePath = "";

    bool enableStreaming = false;
    QString rtmpUrl = "";
    QString streamKey = "";

    int audioSampleRate = 44100;
    int audioBitrate = 128000;
    int audioChannels = 2;
    int fadeInDurationMs = 300;
    int fadeOutDurationMs = 500;

    bool windowResizable = false;
    bool windowMaximizable = false;
};
```

`RecorderConfig` 是一个纯数据结构（POD-like），集中存放所有录制参数。这种设计的好处是：
- UI 层（SettingsDialog）填写参数 → 打包成一个 `RecorderConfig` 对象
- 通过 EventBus 传递给 SystemController
- SystemController 再分发给各个采集/编码模块

整个参数流向是单向的，避免了各模块之间直接耦合。

## 8. 项目模块地图

阅读完以上文件后，可以建立如下模块地图：

```
main.cpp
  ├── CrashHandler::init()          ← 崩溃保护
  ├── Logger::instance().init()     ← 日志系统
  ├── qRegisterMetaType<>()         ← 跨线程类型注册
  ├── SystemController              ← 核心控制器（后续课程重点）
  │     ├── DxGiCapturer            ← 屏幕采集（第5课）
  │     ├── WgcCapturer             ← 窗口采集（第6课）
  │     ├── WinRTCamera             ← 摄像头（第7课）
  │     ├── WasapiCapturer          ← 音频采集（第8课）
  │     └── FFmpegRecorder          ← 编码输出（第9-11课）
  └── MainWindow                    ← UI 主窗口（第12-13课）
        ├── FramelessWidget         ← 无边框窗口
        ├── QGraphicsScene/View     ← 预览画面
        ├── ResizablePixmapItem     ← 图层控件
        ├── AddSourceDialog         ← 添加源对话框
        └── SettingsDialog          ← 设置对话框
```

所有模块之间通过 `EventBus`（第3课）进行解耦通信，`RecorderConfig` 作为参数载体在模块间传递。
