# 仿 OBS 音视频项目 —— 深度学习指南

> 本文档为针对本项目的系统性学习建议，适合希望深入理解音视频采集、编码、多线程架构的开发者。

---

## 一、项目概览

| 维度 | 内容 |
|------|------|
| **类型** | 桌面音视频软件（仿 OBS） |
| **语言** | C++20 |
| **UI 框架** | Qt 6 Widgets |
| **核心技术** | DXGI / WGC / WinRT / WASAPI / FFmpeg / Direct3D 11 |
| **平台** | Windows（MSVC 编译器） |
| **代码规模** | ~4,273 行（21 个 .cpp + 15 个 .h） |

## 二、学习路线图

### 第一阶段：读懂整体架构（建议 1-2 周）

从以下 3 个文件入手，自顶向下理解：

| 文件 | 作用 |
|------|------|
| `main.cpp` | 程序入口，了解初始化顺序 |
| `EventBus.h` | 事件总线，整个系统的"神经网络" |
| `SystemController.cpp` | 核心控制器，连接所有模块的"大脑" |

**建议行动：**
- 画出模块依赖图：`UI → EventBus → SystemController → 各采集/编码模块`
- 在纸上手写一遍完整调用链：用户点击录制 → 到视频写入文件

---

### 第二阶段：逐模块攻克（按推荐顺序）

| 优先级 | 模块 | 核心文件 | 关键知识点 |
|--------|------|----------|------------|
| 🥇 1 | 屏幕采集 | `DxGiCapturer.cpp` | DXGI 接口、IDXGIOutputDuplication、D3D11 纹理 |
| 🥇 2 | 编码录制 | `FFmpegRecorder.cpp` | AVFormatContext、AVCodecContext、pts/dts 时间戳 |
| 🥈 3 | 音频采集 | `WasapiCapturer.cpp` | WASAPI 共享/独占模式、PCM 格式、IAudioCaptureClient |
| 🥈 4 | 摄像头 | `WinRTCamera.cpp` | WinRT MediaCapture、帧池预热、GPU 纹理共享 |
| 🥉 5 | 新式采集 | `WgcCapturer.cpp` | Windows Graphics Capture API、IDirect3D11CaptureFrame |
| 🥉 6 | UI 图层 | `ResizablePixmapItem.cpp` | QGraphicsScene、拖拽 resize、Z-order |

---

### 第三阶段：深挖核心难点

#### 难点 1：多线程数据同步

```
采集线程 → [线程安全队列 / 锁] → 编码线程
```

重点阅读 `QRecursiveMutex`、`QThread` 的使用方式，理解为什么 `Logger.h` 使用递归锁，以及如何避免死锁。

#### 难点 2：音视频同步（最难！）

```
视频帧 PTS ↔ 音频 PTS → FFmpeg 混流 → 同步输出
```

重点阅读 `FFmpegRecorder.cpp` 中的 pts 计算逻辑，理解 DTS 与 PTS 的区别，以及时间基（time_base）的换算。

#### 难点 3：GPU 纹理到 CPU 内存的路径

```
D3D11 GPU Texture → Staging Texture → CPU Map → FFmpeg AVFrame
```

这是性能瓶颈所在，理解为何需要 Staging Texture 做中转，以及如何减少 GPU-CPU 拷贝的延迟。

## 四、高效学习技巧

### 1. 善用版本历史（本项目独有优势）

项目保留了 8 个完整迭代版本目录，这是极宝贵的学习资源：

```
实现录屏/                    ← 最初的 FFmpeg 录制基础
实现音频设备发现/             ← WASAPI 集成
解决混音问题/                ← 多源音频合并
新添直播功能/                ← RTMP 推流
解决程序运行奔溃问题/         ← 稳定性修复
新增WGC采集，优化切换逻辑/   ← 当前最新
```

**建议：** 用 diff 工具对比相邻版本的代码差异，理解每个技术决策背后的原因，比直接看最终代码更有价值。

### 2. 加日志打印

在每个模块的关键路径加 `Logger` 输出，运行时观察实际数据流：

```cpp
// 示例：追踪视频帧的生命周期
LOG_INFO("DxGi: 采集到第 %d 帧，尺寸 %dx%d", frameCount, width, height);
LOG_INFO("FFmpeg: 开始编码第 %d 帧，pts=%lld", frameCount, pts);
```

### 3. 断点调试

用 Qt Creator + MSVC 调试器，在 `SystemController` 中打断点，逐步跟踪一帧视频从采集到写入文件的完整生命周期。

### 4. 画时序图

特别是录制启动/停止的时序，涉及多个线程的协调，画出来才能真正理解：

```
主线程          采集线程         编码线程
  │                │                │
  │ startCapture() │                │
  │──────────────→ │                │
  │                │ startRecord()  │
  │────────────────┼──────────────→ │
  │                │  push frame()  │
  │                │──────────────→ │
  │                │   encode()     │
  │                │                │──→ 文件
```

### 5. 理解关键设计亮点

| 特性 | 实现位置 | 学习价值 |
|------|----------|----------|
| 帧池预热 | `WinRTCamera.cpp` | 减少首帧延迟的工程实践 |
| 事件驱动解耦 | `EventBus.h` | 大型项目架构设计模式 |
| 递归互斥锁 | `Logger.h` | 多线程安全日志的实现 |
| 双渲染管道 | `DxGiCapturer` + `WgcCapturer` | 技术选型与兼容性取舍 |
| 双输出路径 | `FFmpegRecorder.cpp` | FFmpeg 多路复用器使用 |

## 六、一句话总结

> 这个项目覆盖了 **Windows 系统编程 + 多媒体采集 + GPU 编程 + 多线程架构 + Qt UI** 五大方向，建议从 `EventBus.h` + `SystemController.cpp` 入手理解全局架构，再逐模块深入，并配合**对比各版本目录的代码差异**来理解每个技术决策背后的原因。循序渐进，每攻克一个模块都会有显著的收获感。
