## 2. 什么叫“无边框窗口”

普通系统窗口一般由操作系统提供：
- 标题栏
- 边框
- 最小化按钮
- 最大化按钮
- 关闭按钮

而无边框窗口（Frameless Window）的意思是：
- 不使用系统默认标题栏和边框
- 这些东西全部由应用自己绘制和实现

在本项目里，`FramelessWidget.cpp:12`：

```cpp
setWindowFlags(Qt::FramelessWindowHint | Qt::Window | Qt::WindowSystemMenuHint | Qt::WindowMinimizeButtonHint);
```

这行代码就是整个无边框实现的起点。

### 2.1 `Qt::FramelessWindowHint` 的含义

它告诉 Qt：

> 不要给这个窗口使用系统默认边框和标题栏。

结果就是：
- 系统外框消失
- 系统拖动行为消失
- 系统缩放边框消失
- 系统标题栏按钮也不再自动可用

你获得了更高的 UI 自由度，但代价是：

> 原本操作系统帮你做的交互，你都要自己补回来。

这就是 `FramelessWidget` 存在的意义。

## 3. 为什么录屏工具喜欢无边框风格

录屏、直播、创作类桌面工具很喜欢无边框窗口，原因通常有三个。

### 3.1 视觉统一

系统原生标题栏风格受平台影响很大。

而无边框后，应用可以统一：
- 颜色
- 按钮样式
- 圆角
- 间距
- 整体暗色主题

在当前项目里，`mainwindow.cpp:65` 开始就统一设置了深色主题：

```cpp
QWidget { background-color: #2b2b2b; color: #ffffff; font-family: 'Segoe UI'; }
```

这和系统默认标题栏通常并不匹配，所以无边框更容易做出一致观感。

### 3.2 空间利用率更高

录屏工具通常需要：
- 预览区尽量大
- 控制区尽量紧凑
- 自定义顶部工具条

自定义标题栏可以让界面布局更灵活。

### 3.3 更适合品牌化和功能融合

例如你可以把：
- 标题文字
- 状态指示
- 顶部按钮
- 设置入口

融合在同一条自定义栏里，而不是受系统默认窗口框架限制。

## 6. 为什么 `FramelessWidget` 要自己维护一堆状态

在 `FramelessWidget.h:41`-`53`：

```cpp
bool m_isResizable = false;
bool m_isMaximizable = false;
int m_titleBarHeight = 30;
int m_borderWidth = 6;
int m_cornerWidth = 20;
bool m_isMaximizedState = false;

bool m_isPressed = false;
bool m_isDragWindow = false;
int m_resizeDir = 0;
QPoint m_dragPos;
QRect m_restoreRect;
```

这些字段就是作者自己实现窗口系统行为所需的“状态机”。

### 6.1 为什么系统窗口不需要你关心这些

因为普通带边框窗口的这些状态都由操作系统维护：
- 当前是不是在拖动
- 当前是不是在缩放
- 鼠标在哪个边缘
- 最大化前的恢复位置是什么

### 6.2 而无边框以后，这些都必须自己存

例如：
- `m_isPressed`：当前左键是否按下
- `m_isDragWindow`：当前是不是在拖整个窗口
- `m_resizeDir`：当前缩放方向
- `m_dragPos`：按下时鼠标相对窗口的位置
- `m_restoreRect`：从最大化恢复时要回到哪里

所以从本质上说：

> **`FramelessWidget` 在模拟一部分本来属于操作系统窗口管理器的行为。**

## 7. `Direction` 枚举是缩放逻辑的核心

在 `FramelessWidget.cpp:5`：

```cpp
enum Direction {
    None = 0, Left = 1, Top = 2, Right = 4, Bottom = 8,
    TopLeft = 3, TopRight = 6, BottomLeft = 9, BottomRight = 12
};
```

### 7.1 为什么这样设计

它把窗口边缘区域抽象成方向：
- 左
- 上
- 右
- 下
- 四个角

其中四个角是组合值，例如：
- `TopLeft = Left + Top`
- `BottomRight = Right + Bottom`

这样后面判断时可以写成：

```cpp
if (m_resizeDir & Direction::Left) { ... }
if (m_resizeDir & Direction::Top)  { ... }
```

### 7.2 这种写法的好处

比起给每个角单独写一套完全不同分支，这种按位组合更紧凑：
- 角就是两个边的叠加
- 代码复用更高
- 缩放逻辑统一

这是一个很典型的 UI 交互实现技巧。

## 8. `setResizable()` 为什么不只是改个布尔值

在 `FramelessWidget.cpp:17`：

```cpp
void FramelessWidget::setResizable(bool enable) {
    if (m_isResizable == enable) return;
    m_isResizable = enable;
    if (m_isResizable) {
        setMinimumSize(800, 600);
        setMaximumSize(QWIDGETSIZE_MAX, QWIDGETSIZE_MAX);
    } else {
        setFixedSize(this->size());
        setCursor(Qt::ArrowCursor);
    }
}
```

### 8.1 为什么启用缩放时要设置最小尺寸

因为如果允许自由缩放，但不设置下限：
- 窗口可能被拖得过小
- 内部控件布局会挤坏
- 预览区可能不可用

作者这里给了一个很务实的下限：

```cpp
800 x 600
```

### 8.2 为什么禁用缩放时直接 `setFixedSize(this->size())`

这行很关键。

它不是说“窗口永远固定成某个写死尺寸”，而是：

> 把当前尺寸锁住。

这样可以支持这种流程：
- 程序启动后先有一个窗口尺寸
- 用户配置里如果不允许缩放
- 那就把当前尺寸固定下来

这比写死一个常量更灵活。

## 10. `getRegion()`：窗口缩放命中测试的核心

在 `FramelessWidget.cpp:37` 开始：

```cpp
int FramelessWidget::getRegion(const QPoint &pos)
```

这个函数的职责是：

> 根据鼠标当前位置，判断用户正指向窗口哪个边缘/角落。

### 10.1 它是怎么判断的

主要看两组参数：
- `m_borderWidth = 6`
- `m_cornerWidth = 20`

代码逻辑：
- 如果鼠标在四角的 20px 区域内，优先判为角
- 否则如果在四边 6px 区域内，判为边
- 否则判为 `None`

### 10.2 为什么角区域要比边区域更大

因为角拖拽更难命中。

如果角区域也只有 6px：
- 用户很难精准抓住角
- 交互手感差

所以角一般会做得比边更宽松一些。

### 10.3 为什么最大化状态直接返回 `None`

在 `FramelessWidget.cpp:38`：

```cpp
if (m_isMaximizedState) return Direction::None;
```

因为最大化后窗口已经贴满可用区域：
- 不应该还能手动边缘缩放
- 也不需要显示缩放光标

这是符合桌面窗口直觉的。

## 11. `updateCursorShape()`：为什么光标变化很重要

在 `FramelessWidget.cpp:58`：

```cpp
void FramelessWidget::updateCursorShape(const QPoint &pos)
```

### 11.1 这个函数解决什么问题

无边框窗口没有系统自动提供的边缘提示。

如果不主动修改鼠标样式：
- 用户看不出哪里可以缩放
- 体验会很差

所以当鼠标移动到边角时，程序会切换成：
- 水平缩放光标
- 垂直缩放光标
- 对角缩放光标

### 11.2 为什么这不是“纯美观”功能

这实际上是交互反馈的一部分。

因为缩放属于“隐式能力”：
- 界面上没有一个按钮写着“从这里拖动缩放”
- 用户只能通过光标变化得知这个区域有特殊行为

所以这一步对可用性非常关键。

## 12. `mousePressEvent()`：点击后如何区分“拖窗口”还是“缩放窗口”

看 `FramelessWidget.cpp:75` 开始：

```cpp
if (event->button() == Qt::LeftButton) {
    m_isPressed = true;
    m_dragPos = event->pos();
    if (m_isResizable && !m_isMaximizedState) {
        m_resizeDir = getRegion(event->pos());
        if (m_resizeDir != Direction::None) return;
    }
    if (getRegion(event->pos()) == Direction::None && event->pos().y() <= m_titleBarHeight) {
        m_isDragWindow = true;
    }
}
```

### 12.1 这里做了两个关键判断

先判断是不是在边缘：
- 如果是，说明用户想缩放
- 记录 `m_resizeDir`

如果不是边缘，并且位于标题栏高度范围内：
- 说明用户想拖动整个窗口
- 设置 `m_isDragWindow = true`

### 12.2 为什么这个判断顺序很重要

必须先判边缘，再判拖动。

否则当用户点击左上角时：
- 可能本来想缩放
- 却被识别成拖动标题栏

所以这里其实是在解决“交互优先级冲突”：

```text
边缘缩放优先于标题栏拖动
```

这是一条很合理的规则。

## 13. `mouseMoveEvent()`：真正的拖拽逻辑在哪里发生

在 `FramelessWidget.cpp:90` 开始。

这个函数分成三种状态。

### 13.1 状态一：鼠标没按下

```cpp
if (!m_isPressed) {
    updateCursorShape(event->pos());
    return;
}
```

此时只是悬停，不做实际拖拽，只更新光标。

### 13.2 状态二：正在缩放窗口

```cpp
if (m_isResizable && m_resizeDir != Direction::None && !m_isMaximizedState) {
    QRect rect = geometry();
    QPoint gp = event->globalPos();
    QSize minSize = minimumSize();
    ...
    setGeometry(rect);
    return;
}
```

这段逻辑会根据鼠标全局位置去改窗口矩形：
- 左边拖动就改 `rect.left`
- 右边拖动就改 `rect.right`
- 上边拖动就改 `rect.top`
- 下边拖动就改 `rect.bottom`

最后调用：

```cpp
setGeometry(rect)
```

实现实时缩放。

### 13.3 状态三：正在拖动整个窗口

```cpp
if (m_isDragWindow && !m_isMaximizedState) {
    move(event->globalPos() - m_dragPos);
}
```

这就是窗口拖动的核心。

公式含义：
- `event->globalPos()` 是鼠标当前屏幕坐标
- `m_dragPos` 是按下时鼠标在窗口内部的相对位置
- 二者相减，就得到窗口左上角应该移动到哪里

这是无边框拖动最经典的实现方式之一。

## 14. 为什么拖动使用 `globalPos()` 而不是 `pos()`

这是理解窗口拖拽的关键细节。

### 14.1 `event->pos()` 是什么

它是相对于窗口客户区的坐标。

如果窗口本身正在移动，局部坐标系也在变化，不适合直接拿来算全局位置。

### 14.2 `event->globalPos()` 是什么

它是屏幕坐标。

对于窗口移动来说，你真正要关心的是：
- 鼠标现在在屏幕上的哪里
- 窗口左上角应该跟到哪里

所以拖动时使用全局坐标是更自然的。

## 15. 缩放逻辑为什么要结合最小尺寸判断

在 `FramelessWidget.cpp:99`-`111`：

```cpp
if (rect.width() - delta > minSize.width()) rect.setLeft(gp.x());
...
if (rect.height() + delta > minSize.height()) rect.setBottom(gp.y());
```

### 15.1 这是在避免什么问题

如果不做最小尺寸判断：
- 用户可以把窗口拖成负宽度/负高度趋势
- 或者极端压扁到完全不可用

### 15.2 为什么只要超过最小值才更新边界

因为缩放本质上就是在修改矩形边界。

只要改完后的尺寸仍然合法，就允许。
否则就忽略这次边界更新。

这是一种很直接也很稳定的保护方式。

## 16. `mouseReleaseEvent()` 为什么要清空状态

在 `FramelessWidget.cpp:121`：

```cpp
m_isPressed = false; m_isDragWindow = false; m_resizeDir = Direction::None;
updateCursorShape(mapFromGlobal(QCursor::pos()));
```

### 16.1 为什么要重置这么多变量

因为鼠标释放意味着：
- 当前拖拽动作结束
- 当前缩放动作结束
- 当前按压状态结束

如果不清空：
- 后续移动鼠标可能继续误判为拖动/缩放中
- 交互状态会错乱

### 16.2 为什么释放后还要再更新一次光标

因为放开鼠标后，用户仍然可能停留在边缘区域。

这时应立即恢复到当前悬停位置对应的光标，而不是继续显示拖拽过程中的状态。

这属于细节优化，但体验差别很明显。

## 18. `toggleMaximized()` 为什么不直接用 `showMaximized()`

在 `FramelessWidget.cpp:163`：

```cpp
void FramelessWidget::toggleMaximized() {
    if (!m_isMaximizable) return;
    if (m_isMaximizedState) {
        setGeometry(m_restoreRect);
        m_isMaximizedState = false;
    } else {
        QScreen *screen = QGuiApplication::screenAt(geometry().center());
        if (!screen) screen = QGuiApplication::primaryScreen();
        m_restoreRect = geometry();
        setGeometry(screen->availableGeometry());
        m_isMaximizedState = true;
    }
}
```

### 18.1 为什么作者自己维护最大化状态

无边框窗口下，直接依赖系统最大化行为有时会带来：
- 边界不一致
- 拖动恢复逻辑不顺手
- 多屏行为不符合预期

所以作者干脆自己管理：
- 最大化前保存 `m_restoreRect`
- 最大化时占满当前屏幕可用区域
- 恢复时回到原矩形

### 18.2 为什么用 `availableGeometry()` 而不是 `geometry()`

`availableGeometry()` 表示屏幕可用区域：
- 会避开任务栏等系统占用区域

这比直接铺满整个屏幕更符合普通窗口的最大化体验。

### 18.3 为什么要用 `screenAt(geometry().center())`

这是多显示器友好设计。

含义是：
- 当前窗口主要位于哪块屏幕
- 就在那块屏幕上最大化

而不是一律跑到主屏幕。

这对多屏录屏工具尤其重要。

## 19. `changeEvent()` 为什么还要同步窗口状态

在 `FramelessWidget.cpp:135`：


### 19.1 这说明作者并没有完全假设状态只会从 `toggleMaximized()` 改变

也就是说，窗口状态还有可能通过别的路径变化，例如：
- 系统层触发
- Qt 内部状态变更
- 其他地方调用窗口状态接口

### 19.2 这段代码的作用

它相当于一个兜底同步：
- 保证内部 `m_isMaximizedState` 和真实窗口状态一致

这类代码在桌面 UI 开发里很常见，因为：
- 窗口状态不一定只受你一个函数控制

## 22. `applyWindowConfig()`：业务配置如何落到窗口行为

在 `mainwindow.cpp:55`：

```cpp
void MainWindow::applyWindowConfig()
{
    setResizable(m_config.windowResizable);
    setMaximizable(m_config.windowMaximizable);
    if (m_btnMax)
        m_btnMax->setEnabled(m_config.windowMaximizable);
}
```

### 22.1 这里做了两层同步

1. **行为层同步**
   - 调用基类接口决定是否能缩放、是否能最大化

2. **UI 层同步**
   - 如果不允许最大化，就把最大化按钮禁用

### 22.2 为什么不能只做其中一个

如果只禁用按钮，不禁行为：
- 用户仍可能双击标题栏最大化

如果只禁行为，不禁按钮：
- 用户点击按钮却没反应，体验很奇怪

所以这里体现了一个很好的 UI 原则：

> **视觉状态和实际能力要保持一致。**

## 28. `resizeEvent()` 为什么只做 `fitInView`

在 `mainwindow.cpp:209`：

```cpp
void MainWindow::resizeEvent(QResizeEvent *event)
{
    QWidget::resizeEvent(event);
    if (m_view && m_scene) {
        QRectF rect = m_scene->sceneRect();
        if (rect.width() > 1 && rect.height() > 1)
            m_view->fitInView(rect, Qt::KeepAspectRatio);
    }
}
```

### 28.1 这里说明主窗口缩放后，内部不是像普通表单那样简单拉伸

而是要重新适配画布视图。

### 28.2 为什么要保持纵横比

预览区承载的是视频/合成画面。

如果不保持比例：
- 预览会被拉伸变形
- 用户看到的构图和真实输出不一致

所以这里使用：

```cpp
Qt::KeepAspectRatio
```

这对录屏/直播工具来说是很必要的。

这一课最重要的不是“怎么写几个鼠标事件”，而是理解下面这件事：

> **当你放弃系统默认窗口框架时，你其实是在自己接管桌面窗口管理的一部分职责。**

- 配置能力和 UI 状态一致性

- 基类处理通用窗口行为
- 主窗口处理具体业务界面

这是一种很适合学习、也很适合中小型桌面工具项目的设计。
